These observations support improved recovery in the tested legacy cases. Release review
still needs the limitations below; this is not blanket evidence for all workflows.

## A failure the live benchmark caught

The initial candidate Cursor PM exited before delegating, and an Antigravity PM had to
replace a failed Cursor worker. The private capture contained this actual protocol prefix:

```text
[backend] ESC M ESC [ K {"jsonrpc":"2.0","id":1,"result":...}
Error: ACP startup timed out
```

`Engine::next` in `src/backend_runner.rs` tried to parse the entire line as JSON. The native
CLI's startup spinner controls made that parse fail; OMAR discarded a valid initialize
reply and continued waiting. The enclosing 45-second startup timeout then ended the runner.
This was a transport/parser failure, not a model forgetting to manage workers.

`fcd5580` strips only recognized leading terminal controls before parsing JSON. It preserves
the payload and still rejects arbitrary diagnostic text containing JSON. The exact observed
prefix is covered by Rust regression tests and by the deterministic native-protocol peer in
`tests/ci/protocol_runner.py`. The live follow-up uses unchanged model/task settings and
snapshotted binaries. Original failures remain in the result appendix.

## How to interpret the evidence

The suite tests a bounded two-child legacy hierarchy. A passing normal task is not evidence
that every workflow or topology improved. Each healthy backend cell has one seed, and the
OpenCode reset has two seeds. These samples are too small for a reliable general success
rate or speed comparison. Provider load, concurrent cases, native CLI startup and model
sampling all affect timing. Separate batches overlapped, so concurrency was not fixed across batches; do not
interpret their wall times as a controlled performance benchmark.

Both variants passed native compaction for Codex and OpenCode. The tests verify completion
of a native compaction operation; they do not force a full context window or prove that the
same amount of history was discarded. Fresh-conversation reset is a separate intervention,
verified by a changed native conversation ID. The harness sends no replacement task, but
normal launch instructions, files and branch-native recovery mechanisms remain available.

The candidate's durable task/result state (`src/supervision.rs`) survives conversation loss.
Its host reconciler emits reminders independently of the model, and MCP responses and managed
turns project current ownership/results back into context. These mechanisms explain why
recovery can work without the PM remembering to set its own timer. The paired benchmark
compares the whole integration; it does not isolate which mechanism caused a particular win.

## Exclusions and corrections

All declared trials, including missing outcomes, appear in the generated appendix. No failed
trial is silently replaced by its rerun. The earlier calibration runs are separate and are
not scored: they exposed an MCP argument-name collision and isolated Claude trust/auth setup.
A valid Codex/Claude/OpenCode calibration pair passed on both branches.

The initial Cursor fixture lacked workspace trust. Its baseline PM stopped at that prompt;
the Antigravity pair also used Cursor workers. Those pairs are setup-confounded. Both were
rerun with explicit trust and a 300-second budget on both branches, replacing the initial
240-second budget. Their outcomes cannot be used as an unchanged-budget speed comparison.

Several Codex reset attempts were invalid: tmux's escaped launch command was incorrectly
replayed through a shell or decoded with dollar escapes remaining. One trial then failed
cleanup before saving its outcome, and its development binary changed during the run. It
remains a missing/invalid outcome. The final runner preserves argument semantics, snapshots
executables, captures missing outcomes and terminates fixture-owned processes before cleanup.
See `2026-09-17-assessments.json` for per-trial annotations.

## Validation and limits

After the parser correction: workspace tests passed (432 OMAR unit tests, 7 computer-use
integration tests, 3 deployment tests, 24 integration tests and 19 bridge tests), as did
Clippy with warnings denied, formatting, the five required shell jobs, and the Cursor/AGY
protocol runner tests. The workspace run excluded `/opt/X11` from PATH because the local
X11 screenshot test previously hung; it does not establish working X11 capture. Seven
ignored OMAR tests were exercised earlier in this branch's validation, not rerun by the
default workspace command. No GitHub CI run for this integration branch is claimed.

Native compaction/reset for Claude, Cursor and Antigravity, Mission Control execution,
deeper trees, arbitrary graph topology, multi-hour durability, and a multi-seed reliability
study remain unverified. This benchmark supplies concrete release evidence and regressions;
it does not justify an unconditional production-reliability claim.
